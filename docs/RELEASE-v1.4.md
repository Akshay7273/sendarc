# SendBeam v1.4 — Release Gate

The v1.4 milestone (**Native product & distribution**: multi-platform CLI/desktop distribution, shared Go engine architecture, cryptographic supply chain integrity, and self-update engine with atomic rollback) gates release on the checks below, each verified against merged `main`.

Evidence is a deterministic unit/integration test, a verified build artifact in GitHub Actions, or a measured benchmark; every transfer across the matrix terminates with a cryptographically verified whole-file SHA-256 digest comparison.

## 3. Scope Notes & Release Invariants

- **Zero Protocol Duplication:** `sendbeam/1` wire protocol is the single source of truth across all platforms. Desktop and CLI share Go `packages/engine` and `packages/wire`, while Web executes TypeScript `@sendbeam/protocol`.
- **Fail-Closed Security:** Corrupted downloads, mismatched hashes, untrusted channels, missing secrets, or path traversal attempts fail closed immediately without committing invalid bytes.
- **Local State Hygiene:** All configuration, journals, sender records, and secret keys reside in standard OS locations (`docs/state-storage.md`). No cloud telemetry, accounts, or remote storage are required or used.
- **Release Automation:** Tagging `v1.4.0` triggers `.github/workflows/publish.yml` and `.github/workflows/distribution.yml` to compile, package, sign, attest, and attach release assets automatically to the GitHub Release.
