## Scope notes

- **No wire-protocol change.** `resume-auth-v1` is an additive, capability-gated extension
  of `sendbeam/1`; `sendbeam/2` is not introduced. Ordinary fresh transfers are
  byte-for-byte unchanged; legacy peers that never advertise the capability never receive
  resume-auth messages.
- **Capability is intent-scoped.** A host advertises `resume-auth-v1` only when the user
  explicitly selects an interrupted transfer before the fresh rendezvous; a normal send or
  receive never announces it, so one side can never wait for a preamble the other side
  never intends to run. Absence/stripping of the capability makes cross-session resume
  unavailable — never an unauthenticated downgrade.
- **Legacy / no-credential state fails closed.** Pre-PR07 records and journals without a
  resume credential keep their durable data locally; authenticated cross-session resume is
  unavailable and an explicit fresh restart/discard is the only path. Credentials are
  never fabricated or replaced.
- **Fresh state per attempt.** Every cross-session resume uses fresh nonces, derives fresh
  directional keys + salts, and starts counters only under those new values. A failed
  attempt preserves the record/journal and a later attempt uses fresh nonces.
- **Local-only.** Resume is account-free with no server-side file storage, no permanent
  trusted-device identity, no global transfer directory, and no cloud mailbox. Durable
  state is purely local to the device/browser origin.
- Release process (not part of this PR): the `v1.3` tag is created from this merge; the
  release-tag trigger in `publish.yml` then publishes the multi-arch image and CLI
  binaries, as done for `v1.2`.
