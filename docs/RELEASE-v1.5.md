## 4. Security Invariants & Attack Matrix Verification

All security properties are strictly maintained across the entire codebase:

- **Strict Identity Binding:** Display names and local labels are purely cosmetic and local; all cryptographic authorization is bound strictly to canonical `DeviceID` (`sb-dev-...`) derived from the Ed25519 public key.
- **Transcript Freshness & Anti-Replay:** Every `sendbeam/2` trusted session incorporates fresh 256-bit initiator and responder nonces, session timestamps with a strict ±5 minute tolerance window, and ephemeral ECDH keys.
- **Fail-Closed Revocation:** Unpairing or revoking a device purges the pairwise credential (`k_pair`) locally. Any future connection attempts from that device fail closed immediately with `ErrUntrustedPeer`.
- **Auto-Accept Path Confinement:** Auto-accept destinations must be absolute paths (root `/` rejected). All inbound file paths are sanitized via `wire.NormalizeTransferPath()`; paths with parent directory traversal (`..`) or absolute references fail closed and cannot escape the destination boundary.
- **One-Time Isolation:** Standard one-time transfers execute under isolated SPAKE2 credentials and never write to or read from the persistent trust database.
- **Origin-Scoped Browser Storage:** Browser trust records and pairwise secrets reside in origin-isolated IndexedDB databases. Clearing site data predictably revokes all local browser credentials without leaking key material across origins.
